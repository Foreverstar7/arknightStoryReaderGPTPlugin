# 当前技术决定

## 本机阅读与职责

阅读由本机服务提供，不调用模型。React 管页面与交互，domain 管字数／修订，data 管 PRTS 取数与解析，storage 管记录／缓存，server 管业务服务和协议适配。使用现有 SDK、SQLite 和原生动画 API，不为未实现功能新增框架。

## 来源与解析

目录范围固定为 PRTS 剧情一览正文，保留稳定 ID 与源顺序。扫描源字段后明确选择简单或复杂分支流程，人物与图层状态按分支隔离，共同后续只出现一次。

源格式中的固定名称、兼容白名单、资料索引及图层坐标有明确用途与来源；依据、适用范围和变化后的检查见 [PRTS 维护规则](../docs/maintenance.md)。未知正文或资源不能靠猜测兜底。

## 进度与持久化

打开当前剧情后准备该部全部正文以取得字数分母；准备过程只写公共缓存／统计，实际打开正文才登记阅读与执行修订迁移。最后位置和最远进度分开保存，未知分母不当作零。

阅读记录、内容缓存和字数索引使用独立 SQLite 存储。事务支持多进程；清理代次和 historyToken 阻止迟到请求恢复已清数据；旧 JSON 迁入标记防止重复导入。现有磁盘／工具契约的兼容不因内部拆分改变。

## 图片与封面

姓名与资源分别处理，匿名不揭示真实身份。多人匹配需要精确资料与唯一场景资源；原图不可用时只选择有来源的同造型默认，不能确认则占位。网络与解析失败保持可重试错误。

封面按源资料定位，统一 1560:500 外框，批准的非横幅完整显示；两个同名特殊合集因无唯一图片，按稳定 ID 使用不同文字封面。具体 ID、尺寸和资料来源见[封面规则](../docs/requirements.md#封面)。

图片保持原始字节和透明通道，MCP 通过 app-only 元数据分段传输。图片预算及其维护依据见[图片与传输预算](../docs/maintenance.md#图片与传输预算)。

## 页面与设计

位置观察、保存队列和动画各自处理生命周期；状态提交、页面切换和恢复位置保持一致，取消或迟到导航不得覆盖当前页面。保存失败不跳过后续已排队写入。

设计预览复用正式 UI 入口，不维护另一套组件、静态原型状态或独立素材。行为说明只描述当前实现；旧方案只在兼容规则或明确禁用理由需要时提及。

## 运行包与发布

GitHub 保存源码与 CI，npm 保存完整运行包，稳定 marketplace 固定精确 npm 版本。系统 Node 是运行前提；标准 npm pack 内嵌生产依赖，正式入口仅 PRTS，源码和独立开发副本保留 fixture。

普通 push／PR 在 Ubuntu 执行通用检查；标签发布前保留 Windows 运行包与真实 PRTS 验收，覆盖当前目标平台，不设置三平台矩阵。npm 发布 job 在 Ubuntu 使用 OIDC 上传同一归档为 next，仅该 job 绑定 `npm-production` 环境审批。

稳定提升保留手动触发、真实宿主验收确认及标签／回执／registry integrity 校验，不绑定 environment。个人维护项目由同一人发起和批准，手动触发及验收确认已承担稳定提升的发布决定，不增加第二次 environment 审批。稳定 marketplace 始终固定精确 npm 版本。

阅读记录、原文／图片缓存、临时工具和恢复备份不进入发行物。
