## 2026-11-01：先阅读器，后基础搜索

- 决定：优先实现 extension；对话侧首版只提供一个基础剧情搜索工具。台词定位、原文辅助讨论留到以后；不做对话侧续读和进度查询。
- 依据：用户将页面阅读体验作为核心，选择先做基础资料搜索。
- 影响：阅读器所需的数据接口仍需实现，检索不成为阅读器的依赖；搜索可以复用稳定剧情标识与打开篇目列表的路由。

## 2026-11-01：采用 MCP Apps 2.x、React 和原生动效

- 决定：TypeScript + React + Vite singlefile；服务使用拆分的 MCP SDK 2.x，UI 使用官方 `useApp`；入口通过 `openai/ui.entrypoints` 声明，不手写桥接。导航优先复用 View Transitions，不支持时使用 Web Animations，减少动态效果时保持终态。
- 依据：已读取当前官方插件文档、官方 SDK 示例及用户新增的 `create-mcp-app` skill；仓库没有旧技术栈约束。用户要求优先复用成熟能力，且追加主页保留目录及前后篇翻页效果。
- 影响：不引入模型 API key、动画框架或模型侧导航工具。所有内部工具为 app-only，唯一模型可见搜索留到 S5。OpenAI extension 包 0.2.1 的可选 peer 与 ext-apps 2.x 尚不匹配，本轮仅使用有官方示例的声明式入口字段。

## 2026-11-01：本机记录与缓存分别存储，先验证原创路径

- 决定：`StorySource` 为替换边界，首片只启用明确标记的原创 fixture；记录最终使用 SQLite 事务保存版本化结构，缓存单独目录并按最后访问时间过期。定位为段落标识＋段内比例，最远字数独立保存。
- 依据：按需阅读不需要全库导入；fixture 可提供可靠字数分母，真实 PRTS 分母尚未核实。本轮实际观察到宿主同时拉起两个阅读器 Node 进程，因此用 SQLite 负责跨进程锁，不自建文件锁。已核对 Node 官方 SQLite 文档并在本机 24.14.1 验证接口；该 Node 版本仍输出 experimental 提示到 stderr，不混入 stdio 协议。
- 影响：清缓存不能访问记录目录；旧 JSON 单次迁入并保留原文件，损坏记录报错保留。新正文版本与旧进度冲突时显式报错，兼容迁移留后续，不静默伪造。开发旧版页面需要重开以使用新存储，旧版继续写 JSON 不会与新版双向同步。

## 2026-11-01：本机开发插件与运行记录不随安装版本绑定

- 决定：保留根 `plugin.json` / `mcp.json`，用脚本准备本机来源并通过官方 CLI 安装。开发数据在 `.runtime/`，安装后默认使用系统用户数据目录；生成包、依赖和私有运行数据不提交。
- 依据：真实宿主应尽早接入；官方支持本机 marketplace 与 stdio。运行中的旧插件目录出现文件占用，改用新开发版本安装避免直接覆盖。
- 影响：源码不包含旧用户目录或截图路径；安装升级不应删除阅读记录。当前生成产物仅供本机架构，跨平台干净安装与正式发布仍属 S6。没有执行发布、推送或上架。

## 2026-11-01：优先最新稳定版本，并固定项目级工具链

- 决定：用户要求依赖、Node 与 npm 优先最新稳定版本，明确不兼容时才回退。当前选择 Node 26.13.0 LTS + npm 12.2.1；依赖用 npm latest 查询并实测，`npm outdated --json` 返回空对象。
- 依据：Node 官方发布索引的最新稳定版是 26.13.0；npm 的 Node latest 标签却指向 27 alpha，因此不直接采用该标签。npm 12.2.1 要求 Node `^22.22.2 || ^24.15.0 || >=26.0.0`，原本机 Node 24.14.1 不兼容最新 npm，故准备新的项目内运行时后再验证，而非默默保留旧 npm。
- 影响：`.node-version` / `.nvmrc` / `packageManager` 固定组合；Windows 准备脚本从官方来源下载并核验 SHA256，运行时在忽略的 `.local/toolchain/`。本机插件包同时带这份 Node，直接调用它以避免宿主 PATH 选中旧版本；系统全局安装保持原状。其他平台的安装分发仍待 S6。

## 2026-11-01：安装验收必须经过真实插件加载器

- 决定：Windows 包的 `command` 使用 `./runtime/node.exe`；安装后的独立 MCP 检查之外，增加 `probe:host`，通过官方 app-server 的 `plugin/read` 与 `mcpServerStatus/list` 验证插件组件和入口发现。最终入口可见和打开仍由实际宿主操作确认。
- 依据：用户反馈 0.1.3 主侧栏无入口；同版本宿主加载器明确报错 `Agent Plugins stdio command must be a bare executable name or a contained ./ path`，插件详情返回空 MCP 组件。原命令 `${PLUGIN_ROOT}/runtime/node.exe` 在独立探针手动展开后可运行，因此此前探针漏掉了加载器约束。0.1.4 修复后目录发现通过，用户确认入口可打开。
- 影响：保留 app-only 内部工具和原有全局入口元数据，不为入口缺失向模型暴露额外工具，也不修改桌面客户端。后台发现与真实 UI 打开分别记录。

## 2026-11-01：普通导航与书籍翻页分别编排

- 决定：普通导航只捕获完整内容区域，封面只在有对应封面目标的主页／篇目页之间独立迁移。相邻篇目另捕获正文纸页，新页不透明托底，旧页绕页边翻动并带阴影，整个效果裁剪在正文区域内。延续原生 View Transitions 与 Web Animations。
- 依据：用户在真实宿主中观察到切换闪烁，并再次要求类似书籍的翻页。浏览器抓帧确认旧加载遮罩会使整个页面短暂变暗；旧版普通页面与正文独立动画也没有共同的交接时序。实看新书页中间帧发现透视越过正文边界，已加裁剪。
- 影响：加载保留原页面，延迟小提示不进入转场快照；新数据和恢复位置一并提交，取消导航以最新意图为准。不新增动画依赖，不改变纵向阅读或进度规则。增加慢加载、翻页中间帧及回退／打断检查；宿主端视觉复核仍独立记录。

## 2026-11-01：按 Kindle 横向刷新方向修正动效

- 决定：本条替代上一条中的相邻篇目 3D 旋转方案。下一篇从右向左、上一篇从左向右，用柔和的窄边界渐进替换正文，旧页托底；整页内容保持平面。使用原生 View Transitions、注册 CSS 属性和渐变 mask；缺少快照 API 时回退为短距离平面滑移，减少动态效果时直接到终态。
- 依据：用户指出 0.1.5 实体书式旋转不符合意图，明确要求查阅 Kindle 漫画的水波式切换。已查到实拍页面及 [KOReader 相关实现作者说明](https://github.com/daIvanCode/legacy-kindle-pageflip-animations/blob/main/README.md)，其描述为 Wipe／Reveal 的窄竖条渐进替换；实拍视频页加载超时，没有宣称完成视频观看。该实现依赖墨水屏帧缓冲和刷新波形，不适用于 Web 宿主；本项目复用浏览器原生动画能力，不引入卷页库。
- 影响：不改变纵向连续正文、阅读记录或相邻篇目路径；更新需求中先前被误解为纸页绕边翻动的描述。新增检查断言两页不旋转／移动、波前按相反方向经过，保留中间帧供实看；不宣称逐像素复刻 Kindle 硬件。

## 2026-11-01：固定顶栏与来源提示条退出转场快照

- 决定：根节点不参与 View Transition 捕获，只动画内容区域及必要封面；整个动画层按内容区域上边界裁剪，上边界向上取整至 CSS 像素，避免半像素边界擦到提示条。
- 依据：用户截图标记的提示条在篇章目录进出时闪动，本仓库已实际复现；上移的内容快照进入了提示条下沿。根捕获退出并按小数边界裁剪后仍剩下边沿像素变化，改为取整边界后，四条进出路径在 20%／50%／80% 帧的来源提示条截图与切换前完全一致，浅深两主题均通过。
- 影响：继续保留数据来源标记与已有封面迁移；动画不再覆盖固定导航和提示条。测试等待实际路由完成后再读持久进度，避免把点击回调尚在异步保存时的旧快照当成最终记录。

## 2026-11-01：已核实的篇目字数与当前阅读索引独立于内容文件

- 决定：给阅读记录增加向后兼容的可选 `totalWords`，当前已打开正文直接提供本篇分母，其余篇目未知时全剧情比例继续未知。目录／原始正文属于可清理缓存；保存已打开正文的位置使用内存中的最小字数／段落索引，不为滚动保存重新下载已清除内容。
- 依据：按需读取下没有已核实的整部字数元数据；浏览器不应为了百分比取得未读正文。新增断网回归实际复现了清缓存后保存位置回源的问题，原先 fixture 无网络掩盖了该问题。
- 影响：保持 SQLite 原版本及原记录，不清除旧 fixture 记录。清缓存保留位置、最远进度和已知总字数；该规则不实现跨修订迁移，正文版本冲突仍明确保留原记录并报错。跨进程清理竞态、真实图片缓存与其他脚本形式留对应后续切片。
