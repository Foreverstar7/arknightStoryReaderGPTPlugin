## 原因及实现

0.1.20 的 645 篇均已取到文本，失败发生在本地解析。首个阻断点为 multiline 314、多段字幕 101、animtextclean 98、gridbg 33、largebg 28、冲突重复参数 8、模板字段／分组 5、Decision 数量不符 5、其他 53。每篇最初只报告一个错误；不是 645 次网络故障，也不是源站缺少 645 篇剧情。

本轮核对了 [PRTS ScenarioSimulator](https://prts.wiki/w/Widget:ScenarioSimulator)、[StoryPlayer](https://prts.wiki/w/Widget:StoryPlayer)、[工具库 String.toObject](https://static.prts.wiki/assets/scenario/krliov.toolbox.js) 及 StoryPlayer 页面实际引用的 [播放器模块](https://static.prts.wiki/widgets/production/StoryPlayer.DH9HUkmm.js)。源副本及独立复核脚本位于忽略目录 `.ai/local/compat-0.1.21/`，不随插件打包。

- `multiline` 与同 ID 的 `subtitle/sticker multi` 累积片段，按来源结束／控制流边界输出；人物状态取片段共同可确认的部分。`hidelog` 的字幕不混入阅读日志。
- `animtext` 和 `spellsticker` 保留 `<p=N>…</>` 中的可见文字，时序和样式参数不计字数。`\n`、`{@nbs}`、`{@s}` 按显示语义处理；未知动画文字分段仍失败。
- `gridbg`、`verticalbg`、`largebg`、`animtextclean`、`skipnode`、`stickertween` 是演出／清理指令；`imgeffect` 按明确图片引用输出原位 CG。人物自定义槽位保留源名，不把 `n` 猜成 `m`，不凭匿名名猜立绘。
- 模板前允许来源通知和章节标题，但只读唯一剧情模拟器的正文区域；仍验证字段、分组和尾部边界。
- 工具库按参数出现顺序赋值，故重复参数以最后一个为准。这是对 0.1.20“冲突值拒绝”的有证据修正，不是通用的容错猜测。
- Decision 的重复值允许多个选项指向同一后续；多余 values 不生成虚构选项。复杂条件保留来源顺序、共同后续一次及分支人物隔离。源条件无法关联到可达选项时保留该段正文，并明确标注原条件，人物状态独立。
- Warp 只有找到 Label 才跳转；本轮出现的无 Label 标记按来源播放器顺序继续并提示。存在 Label 的新形式仍拒绝，等待来源核对。
- 所有新正文使用 `prts-script-v3:<hash>`。旧缓存保留原始 Wiki，可离线按需重解析；旧字数不会混充新分母。准备正文不迁移阅读记录，真正打开时沿用原修订迁移规则，原记录及不确定状态保留。

## 必要固定规则的范围与维护

通用参数解析不能判断拼写错误究竟是新指令还是源错误，因此 `prts-compat.ts` 只列出本次实际核对、在来源播放器中不产生正文或人物更新的指令，且约束允许参数名，拒绝额外正文。每次命中均产生来源说明，不静默改写成“可能正确”的指令。

| 明确例外 | 来源值／允许参数 | 处理与限制 |
| --- | --- | --- |
| `daley/dealy/delau/delat/delayt` | 源脚本拼写，`time` | 不产生正文，不补演出时长 |
| `palysound/musicvolune/stopmucis` | `name,volume`／`volume,fadetime`／`fadetime` | 不影响阅读正文，不猜音乐状态 |
| `chaa/dialo/dialogs/charslsot/duration` | 源脚本拼写，无参数 | 不将其改写为人物或对白指令 |
| `glitchtween` | `slot,glitchto,duration` | 仅来源中的演出参数 |
| `consumeguideonstoryend` | `target,subsignal,showanyway` | 游戏流程标记，无阅读正文 |
| `usewhiteloadingmaskonfinish` | 无参数 | 结束遮罩标记 |
| `fadestyle:` | 来源切入样式的冒号拼写 | 仅兼容此键，并提示；不放宽任意参数语法 |
| `GotoPage(dest="home")` | G2H/END 的末尾游戏返回标记 | 保留 0.1.20 的唯一参数、末尾无后续限制 |

这些值取自公开源快照，不是逐剧情资源地址表。来源新增参数、文字、控制流或播放器实现变化时，应重新比对源播放器、更新对应原创回归并重跑全库；不能扩大为忽略所有未知指令。无 Label Warp 的限制、模板名称及视频来源链接同样在源码注明依据。固定名称变化会触发明确解析错误，而不是悄悄返回空正文。

## 设置及界面验收

自动图片为原生按钮语义的 switch，显示开启／关闭；主题采用“主题跟随系统”与“深色模式”两个 switch。跟随时深色开关只反映系统／宿主主题且不可改，关闭跟随后保留当前有效主题，兼容已有 system/light/dark。保存失败恢复已保存状态；支持 Space、Enter、触摸和可见键盘焦点。没有新增依赖。

缓存操作更名“清理剧情文本和图片缓存”，说明同时清理人物及资源映射，保留阅读记录、设置和已核验字数。单部／全局历史清除仍独立确认，原页面路径不变。

实际打开 `docs/design/reader-preview.html` 对照，检查 320×760、768×900、1440×900、1024×400、浅深主题及减少动态效果。面板沿用右侧窄浮层、细线、正文宽度和金色强调；区别是按最新需求加入主题开关并调整数据管理顺序／文案。小窗口通过面板内滚动访问操作，没有横向溢出或整体缩放。新增视频卡与展开的来源说明也在 320／1440 浅深主题检查；正文仍纵向阅读，旁白及对白正文对齐。截图仅放 `.ai/local/screenshots/compat/`。
