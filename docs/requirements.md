# 明日方舟剧情阅读插件需求

更新：2026-11-05

本文件由讨论草案迁入独立开发仓库，作为首版需求输入。已确认的规则、实施建议与待验证事项按各段标注区分；交互设计见 `design/`。

## 当前方向与阶段

先做面向 PRTS 方舟剧情的阅读器：通过官方侧栏入口，在阅读器内选章，以类似代码审查的清晰排版阅读，按需联网获取并缓存内容。当前不预下载整库。

前期独立环境中的最小测试插件曾完成安装并显示“桌面宿主已连接”，仅证明当时页面与宿主的通信；该实验未迁入本仓库。此后本仓库已实现真实剧情、分支、图片、缓存与阅读记录。2026-11-04 当前源码为 0.1.24，用户认为阅读器功能大致完成，现先关注重构；实际安装、平台与宿主验证范围以 `.ai/STATUS.md` 为准，旧实验及下方历史讨论不替代当前验收。

## 当前开发阶段

- 用户已认可当前交互方向，决定在独立仓库开始正式开发。现在无需继续等待前期学习流程完成。
- 先实现 extension 阅读器及其必需的数据能力，再增加一个面向对话的基础剧情搜索工具。
- 技术栈、SDK 和本机持久化方案由实现时结合当前官方文档与目标客户端验证确定；稳定的页面和业务规则不因此从头重做。
- 目标是开源并让其他人下载安装。源码开源、本机安装、对外分发和官方目录上架分别验证；发布限制不作为当前本机开发的前置条件。
- 2026-11-04 已确认需要项目介绍、下载和安装说明网站；不做网站内在线阅读、正文代理或远端阅读记录。当前网站未制作、域名未购买，暂缓建设，仅列入后续发布事项，先处理重构规划。
- 2026-11-04 用户确认先做桌面多平台预适配：Windows、macOS、Linux 的 x64／ARM64 在各自系统准备工具链、构建与打包；README 必须明确只有 Windows 实测，其他系统／架构尚未验证，不将假设兼容写成已验收。此项不扩展移动原生端或跨设备同步。
- 开源发布与素材分发事项在发布准备阶段处理；[接入参考](integration-notes.md)记录官方资料和实现验证重点。

## 重构目标与约束（2026-11-04 已确认）

- 保持现有阅读功能、交互、来源语义和记录，形成清晰的代码职责；删除无实际用途的抽象、层次和面向假想扩展的设计，优先普通函数、模块与已有成熟工具。
- 去掉可避免的硬编码：优先从已有源数据、权威配置或明确公式取得值，删除生产代码中的测试专用数据和重复定义。仅搬到常量文件不算消除；无法等价推导的来源协议或已确认展示规则保留窄范围、出处、适用条件与维护方式，不猜图片地址或角色身份。
- 去掉对不可达内部状态的防御及重复校验：在入口和类型中建立不变量后删除多余兜底、空值分支与异常处理。不以非空断言、强制转换、吞错或伪造默认值掩盖外部数据问题。
- 外部网络／源数据、磁盘旧记录和已存在的异步／多进程竞争仍按实际风险处理。新旧版本迁移及清理后不复活等保护有明确职责；减少防御代码不改变这些已确认行为。
- 逐片实施和验证，硬编码、冗余保护与过度设计的清单及安排见 [重构计划](refactoring-plan.md)。2026-11-05 既定重构已本地完成，实际验证和支持边界以 `.ai/STATUS.md` 为准；基础搜索仍是后续未完成项。

## 阅读体验与首版范围

- 采用官方扩展接口，不修改桌面客户端文件。
- 在阅读器内选择剧情并连续阅读，不要求每读一章都返回原网站找链接。
- 只做阅读，不做批注；“类似代码审查”指阅读布局，不是文本差异审查。
- 保存本机浏览历史与阅读位置，不需要跨设备同步。
- 通用网页提取仍是后续方向；在线找文章、实时重排网页是最初的实现设想，不是必须保留的功能路径。
- EPUB／MOBI 暂不纳入范围。

首批目录以 [PRTS 剧情一览](https://prts.wiki/w/剧情一览)正文为边界。按分类、活动或章节、剧情条目组织入口，保留源站顺序；不缩成只有“主线”一类，也不顺着页面导航额外扩展其他内容。

干员密录、干员专属特殊剧情暂不处理，不另接干员相关的独立目录。

## 页面划分与目录页布局

2026-11-01 已确认：阅读器分为剧情总目录、篇目列表和剧情阅读三个内部页面，在同一个插件容器内切换。已有可交互 HTML 作为观感、布局、动效和操作路径的实现参考。

页面需求与主要交互已基本收束。extension 是核心体验，MCP 对话搜索作为随后增加的附加能力；字号、间距和浮层尺寸可结合真实宿主作常规适配。

目录页面已确认的结构：

- 主区域按分类连续排列，每个分类以分类名称（如“主线”）和分隔线作为分区标题，下方排列对应剧情的卡片。
- 一张卡片对应一部剧情（一个活动或主线章节），其中包含若干具体篇目。剧情卡片的视觉样式参考用户提供的截图，保留封面、名称、类型标签和阅读百分比。
- 左侧提供分类目录，选择后快速跳转到主区域对应的分类标题处。
- 2026-11-02 已确认：页面分类及顺序为“主线、支线、故事集、集成战略、生息演算、四月辑录、其他”。PRTS 正文中的普通“剧情”合集在页面称“故事集”；特殊剧情、危机合约、荷谟伊智境、保全派驻、卫戍协议、多维合作等零散入口归“其他”，卡片保留具体类型。当前不另外拆分插曲／别传，不扩大目录范围。
- 各分类内部仍保留本草案限定的 PRTS 剧情一览正文顺序；页面重新分组不改变剧情／篇目标识或阅读记录。
- 阅读百分比按正文阅读字数统计，不按已读篇数占比计算；字数口径、已读判定及跳读规则见“阅读字数与整体进度”。
- 2026-11-03 已确认：首页进度使用白底圆环，中央为百分比，彩色弧段随已读比例增长；从未实际阅读的剧情显示 0%。有旧阅读记录但统计暂不齐全时，圆环显示短横线并提供可访问说明，不再显示“总字数待核实”，也不伪造百分比。
- 目录封面在卡片进入可视区域时自动加载并缓存，已有缓存直接复用。
- 2026-11-02 已确认：点击“主页”恢复本次打开阅读器期间上次离开总目录的位置；从篇目列表或正文返回均适用，已经在主页时不跳到顶部。窗口宽度变化后优先恢复到同一段剧情卡片；此浏览位置独立于正文阅读进度。
- 2026-11-03 已确认（替代 11-02 的临时尺寸限制）：主页与篇目页的封面外框统一为 **1560:500**，标准原图 **1560 × 500** 完整等比显示。四月辑录 2020—2026 改用「活动一览」中显式链接到对应年份的现成横幅，由目录唯一 APF-YYYY/NBT 关联，实际地址经 imageinfo 解析；不拼图片地址或固定七条映射。
- 主线 EP00—EP04（黑暗时代·上、黑暗时代·下、异卵同生、二次呼吸、急性衰竭）使用「关卡一览/主题曲」对应章节引用的 512×512 原图，完整等比显示并统一背景填充，不拉伸、不裁切。原图包含插画、标题和章号；旧记录将其作为不适用章节标识排除的判断已修正。
- 按稳定 ID 区分两部同名合集：`prts:主线剧情/特殊 · 剧情` 使用应用文字封面「主线补充剧情」（8 篇）；`prts:活动剧情/特殊 · 剧情` 使用同风格「活动补充剧情」（3 篇）。它们不伪装为 PRTS 图片，不显示加载失败。`prts:活动剧情/特殊 · 危机合约`（早期合约／荒芜行动共 3 篇）使用源站通用「活动名称 危机合约.png」（463×121）加统一背景，仍经 imageinfo 取得地址，不用当前作战赛季或单季海报。目录成员、源 ID、顺序、阅读记录与导航范围不变。
- 「日暮寻路」保留现有 1560×500 原图，单张图片取数上限为 **20,000,000 字节**；不采用源站缩略图、不扩大正文／JSON／映射上限。传输可分段，但页面须重组原始字节，保留 MIME／格式校验、缓存和独立重试。来源规则变化时旧封面资料按需重验，不清阅读记录、不预下载整库。
- 除上述批准的完整原图与文字封面外，未知来源尺寸仍显示「封面尺寸待适配」，不一概放行或裁切。此规则不限制正文 CG、背景、人物立绘或已支持的 PNG/JPEG/WebP/GIF 编码。
- 点击剧情卡片时，始终进入该部剧情独立的篇目列表页面，有无阅读记录均使用同一入口路径。
- 2026-11-02 已确认：剧情卡片与篇目卡片的 hover 仅将鼠标改为手形，背景、边框和文字不变色，卡片不上浮；键盘操作仍保留可见焦点框。

## 篇目列表页面

已确认：

- 篇目列表为独立页面，展示所选剧情中的具体篇目；选择篇目后进入剧情阅读页面。
- 该部剧情有阅读进度时，提供“继续阅读 + 章节名称”入口，其中名称对应上次阅读的具体篇目；点击后恢复该篇目与阅读位置。
- 该部剧情没有阅读进度时，用户从篇目列表选择具体篇目开始阅读。
- 篇目列表采用从左到右的横向浏览，支持左右滑动；剧情阅读页面的正文采用上下连续滚动。
- 篇目采用横向交错布局，中间为一条水平主线，按篇目顺序从左到右上下交替排列：章节 1、3 在主线上方，章节 2 在下方，后续依此排列。同一页面展示相邻篇目，超出可视范围的内容通过左右滑动浏览。
- 篇目列表不放“向前／向后”按钮；通过直接拖动横轴区域、横向滚动和一条可拖动的浏览线切换可见篇目。
- 每个篇目块展示章节编号、章节名称、小字章节简介及该篇阅读百分比，采用文字布局，不放缩略图。单篇进度用于帮助用户定位整部剧情尚未达到 100% 的原因；剧情总目录卡片同时展示整体阅读百分比。
- 2026-11-02 已确认：整张篇目卡片可点击，包括标题、简介、阅读进度与留白，均从篇首打开正文；拖动横轴不能误触打开。简介失败时的“重试”保留独立操作，只重试简介，不进入正文；点击、触摸和键盘均应可操作。
- 章节简介优先采用 PRTS 现有的关卡介绍；找不到对应介绍时隐藏简介这一行。

顶部布局：左侧放导航入口及“最近阅读 + 章节名称”快捷入口，右上角保留设置入口；当前剧情名称放在页面标题区，该部剧情有阅读进度时的“继续阅读 + 章节名称”也放在标题区内。

2026-11-01 取数抽样：[GT-1 日正当中](https://prts.wiki/w/GT-1)关卡页包含一段简短介绍，且列出的行动前、行动后剧情入口使用同一个通用剧情图标。关卡介绍可作为简介的候选来源，但不能由此断定所有篇目都有专属简介或缩略图。

## 剧情阅读页面

已确认：

- 正文采用上下连续滚动阅读。
- 对白采用左右分栏，左侧为姓名，右侧为对白内容。
- 以一段发言为显示单位，左侧只显示一次姓名，右侧可包含多行文字；对白因排版换行时不重复姓名。
- 旁白统一左对齐，独立成段；左侧姓名栏留空，文字与右侧对白正文的起点对齐。
- 页面上方提供“主页”和“篇章目录”入口：“主页”返回剧情总目录，“篇章目录”进入当前这部剧情的篇目列表。
- 2026-11-01 补充：回到主页后仍保留顶部“篇章目录”入口，进入最近实际阅读剧情的篇目列表；浏览其他目录不替换这个阅读记录。首次使用且没有已读剧情时可隐藏该入口。
- 顶部栏左上角放“主页／篇章目录”导航及“最近阅读 + 章节名称”快捷入口；最近阅读按实际打开正文的记录确定，浏览其他目录不替换该入口，点击恢复对应章节的最后阅读位置。无阅读记录时隐藏该入口，已处于该章节时保留当前阅读位置。右上角为阅读进度与“设置”，进度紧邻设置按钮左侧。顶部栏在向下滚动时保持可用。
- 正文左侧常驻当前剧情的篇章列表，当前篇目高亮；点击列表项从篇首打开该篇。窄窗口下列表收为可展开的左侧栏，正文随宽度重新排版，页面高度随窗口调整。
- 阅读页面同时展示当前篇章的已读百分比和整部剧情的总已读百分比，与篇目列表、剧情总目录使用同一套进度记录并同步更新。
- 正文末尾提供“上一篇／下一篇”，用于在相邻篇目之间切换。
- 2026-11-01 更新：用户澄清上一篇／下一篇参考 Kindle 漫画的横向水波式切换：一道柔和的边界从一侧扫到另一侧，逐步替换正文，前后篇方向相反。页面内容保持平面，不采用实体书卷曲或整页 3D 旋转；效果限于正文区域。正文仍采用纵向连续滚动，不改成分页阅读。
- 直接点击篇目列表中的篇目时，从篇首开始阅读；“继续阅读”入口恢复最后阅读位置。
- 默认模式下，悬停姓名显示“点击查看立绘”提示；点击姓名在附近浮层中显示立绘，再次点击该姓名、点击其他位置或按 Esc 可收起。CG 在正文原位置展开。
- 2026-11-04 用户调整：正常立绘浮层只显示图片及下方小号 PRTS 来源链接，不重复显示姓名，不显示关闭按钮或“按此处场景资源显示，姓名保持原文”说明。保留无障碍名称、键盘关闭及链接操作；默认图、占位和加载失败仍显示必要状态与重试。
- 辅助功能收纳在右上角的“设置”入口中，包含最近阅读、正文图片自动显示开关、刷新本章和数据管理，以辅助面板承载。
- 2026-11-03 后续反馈：主题与“自动显示图片”均改为 toggle 控件，支持键盘、明确当前状态，保留设置持久化及既有偏好的兼容。主题用“主题跟随系统”及“深色模式”两个开关；跟随时深色开关反映系统／宿主主题并禁用，关闭跟随后保留当前有效主题，继续支持 system/light/dark。
- 2026-11-03 用户选择：源脚本中的视频保留明确的 PRTS 视频来源入口，本轮不加入阅读器内播放、不伪造视频文字转录。纯视频不创建文字阅读记录或改变最近实际阅读；混合篇保留文字及视频入口。源脚本无法关联的条件保留正文和明确来源说明，不猜补选项或人物。
- 2026-11-03 补充：每部剧情的篇目列表页提供“清除本剧情阅读记录”，清除该部的续读位置、最远进度与最近阅读记录，保留其他剧情；操作完成后留在当前目录。设置中的全局操作明确写为“清除全部阅读记录”，与缓存清理放在“数据管理”分类中，位于“最近阅读”之前，不放在面板最下方。两种清除均说明范围并要求在页面内确认。

进度展示格式建议：在设置按钮左侧用小字显示“本篇已读 XX% · 全剧情已读 XX%”，随顶部栏保持可见。具体间距在交互稿中验证。

## 视觉风格与动效验证

- 用户希望页面包含明日方舟元素。当前交互稿采用档案式编号、细线、斜向几何装饰及克制的强调色；剧情正文保持清晰的阅读排版，具体视觉风格待体验后调整。
- 用户希望页面之间有连贯的过渡。参考意图为：从主页点击剧情卡片时，卡片向外延展覆盖主区域并进入篇目列表；从篇目列表继续阅读时，正文由上向下揭开。这些描述是参考，不是必须照做的动效规格。
- 第一版封面放大至铺满画面再消失的转场已被用户指出生硬，当前改为封面在主页卡片与篇目列表页头之间移动和缩放，页面主体短距离滑移交接；从正文直接回主页采用轻量滑移，不生成铺满画面的封面。正文保留纵向揭幕与返回收起，相邻篇目采用横向渐进替换的过渡，尊重系统的减少动态效果偏好。顶部导航和数据来源提示条保持在转场之外，不应被内容快照擦过。

## 阅读字数与整体进度

已确认采用以下规则计算各处展示的单篇和整体阅读百分比：

- 整体进度为各篇已读字数之和除以整部剧情所有篇目的正文总字数。
- 2026-11-03 已确认：打开某部剧情后自动加载该剧情的全部篇章正文，按统一口径取得完整分母。仅限当前打开的剧情，不预下载整库；目录先展示，可边加载边阅读。预取不创建已读记录、不改变最近阅读或位置，不获取正文图片／图片映射。
- 篇目列表显示已加载篇数和完成后的总字数；部分失败保留成功结果并支持重试，缺失篇章不能按零字数凑分母。离开剧情停止排队请求，已经发出的请求可完成。重新打开剧情继续使用缓存并补取缺失正文。
- 统计索引持久保存篇目标识、来源修订与字数，独立于正文缓存和阅读历史；清缓存不丢分母，清历史不删除公共统计。检测到已有记录与新正文修订不一致时，不混用两版进度，实际阅读时按修订迁移规则处理。
- 单篇阅读百分比为该篇已读字数除以该篇正文总字数，并在篇目列表与当前篇章的阅读页面中展示。只有达到该篇完整正文末尾才显示 100%；整体进度同样避免因四舍五入将未完成状态显示为 100%。
- 正文字数包括对白、旁白、选项及各分支正文；姓名、界面标签、演出指令不计入，分支合流后的共同正文只计一次。
- 已明确解析为纯视频的篇目不计算文字百分比、不参与文字完成判定；视频和来源说明不计字数，含视频剧情的进度明确只统计文字。未取得或解析失败的正文仍是未知，不能作为零字数补齐分母。
- 各篇按最远读到的正文位置估算已读字数；回看不降低进度，重复阅读不重复增加字数，未打开的篇目不计为已读。用户接受此方式下直接拖到篇末会将该篇视为已读。
- 上次阅读位置与最远阅读进度分别保存：“继续阅读”恢复最后离开的位置，整体进度使用最远阅读记录。

按上述规则处理阅读路径：

- 回到前面的已读部分时，整体完成度保持；最后阅读位置随本次实际停留位置更新。读过此前最远位置后，新增字数才增加整体完成度。
- 整部剧情读完后重新打开或重读，整体完成度保持 100%，不会自动清零；“继续阅读”仍跟随最近一次阅读的位置。
- 跳到后面的篇目时，只计入该篇实际读到位置之前的字数及此前各篇已累计的字数，中间未读篇目保持未读；不按所跳篇目在全剧情中的位置直接推算整体百分比。
- 同一篇内直接拖动到后面时，按该篇新的最远位置增加已读字数，这是已接受的位置估算规则。

## 从公开原始页面获取剧本

```text
PRTS 剧情一览
    → 取得分类、章节、剧情条目与页面链接
    → 用户选择剧情
    → 优先读取本地缓存；无缓存时获取原始 Wiki 文本
    → 提取并解析“文本数据”及资源引用
    → 展示正文、分支与按需查看的图片
```

公开读取入口：

```http
GET https://prts.wiki/w/{页面标题}?action=raw
```

例如 [W2G/BEG 原始页](https://prts.wiki/w/W2G/BEG?action=raw)。2026-10-28 实测无需登录、Cookie 或访问令牌，返回 HTTP 200，内容类型为 `text/x-wiki; charset=UTF-8`。这是公开的 Wiki 源码，不是 JSON；没有对游戏客户端文件解包或解密，HTTPS 本身仍提供传输加密。

抽样页面包含“文本路径”“剧情类型”“剧情分组”“文本数据”等字段。解析要保留角色显示名、对白、旁白、选项及分支关系，区分文字结构和演出指令，不能直接删除所有方括号内容。原始剧本和图片引用应保留，不预先固定为只保存渲染后的 HTML。

## 保留全部分支，共同后续只展示一次

首版完整保留各选项及其对应分支，按选项分组展示；合流后的共同剧情只展示一次。当前以完整阅读为主，不先做只能选择一条路线的交互式播放。

各分支应独立计算人物状态；不能把互斥分支顺序执行，让上一分支的立绘错误地流入下一分支。合流识别与状态继承仍需实现验证。

## 立绘优先剧情资源，身份匹配必须有来源

对白显示名与人物资源引用是两种信息。`[name="…"]` 决定显示姓名，`Character`／`CharSlot` 等指令控制人物资源、槽位和焦点。PRTS 播放器通过资源映射选择具体图片，不是搜索姓名后拿第一张立绘。

例如 `avg_npc_2321_1#6$2` 包含人物资源组、条目序号和资源分组。分组可能对应姿势、装备或造型变化，不能统一理解为“皮肤编号”。已验证同一 NPC 的 `#6$1` 与 `#6$2` 分别对应持盾和无盾图片。

阅读器只需按剧本维护人物状态，为每条对白保留当时的资源引用，供查看立绘时使用，不必复刻完整剧情动画。

- 保留原显示姓名；不能因为资源 ID 指向已知角色，就把“？？？”改成真实姓名。
- 多人场景需跟踪槽位及焦点，不能只取最后加载的图片。
- 焦点是画面线索，不保证就是对白说话者。对应关系不明确时，不猜测、不展示错误立绘。
- 保留 PNG 透明通道，不把透明区域的 RGB 纹理显示出来。

2026-11-04 用户确认的恢复与兜底规则：

- 优先显示剧情明确指定的原始资源。兼容映射键大小写和引用分隔符周围／末尾的多余空白；新版映射遗漏时查有来源的旧版索引，不模糊搜索姓名或猜 URL。

- 原表情或姿势不可用，而同一角色已可靠确认时，可以显示有明确依据的默认立绘，优先保留当前造型。当前实现仅接受同一资源组／body 的显式默认序号或 `normal` 别名，不把任意数组首项当作可靠默认；没有这样的依据则占位。
- 多人场景先尝试有来源的身份匹配：读取显示名同名 PRTS 资料页，只有 CharinfoV2 中的“干员名”精确一致，且“干员id”与当前场景唯一资源编号在完整边界上对应时，才选择该资源。保留场景表情／造型；原图缺失后仍按既有默认图规则处理。不新增逐角色姓名表、别名表或图片 URL 特例。
- 2026-11-04 用户追补：本次只接受通用匹配规则；如果必须增加角色专用硬编码，就不处理该案例。匿名、无可靠对应、同一身份仍对应多个不同资源时保留占位。焦点、相似姓名、称呼和数组首项不作为依据；不扩展为无场景资源时搜索任意角色图片。
- 剧情原图、默认立绘、中性占位、网络／解析／格式失败保持可区分。默认图明确说明并可重试原立绘，占位可重新核验；真实请求或解析错误保留错误与重试，不能统一转换为占位。诊断保留请求引用、选择结果及来源依据。

## 图片默认手动查看，可开启自动显示

正文图片开关的工作名称为“自动显示图片”，默认关闭。关闭的是正文立绘和 CG 的自动获取与显示，仍允许用户主动查看。目录封面按进入可视区域时自动加载并缓存的独立规则处理。

| 内容     | 自动显示关闭（默认）                                                           | 自动显示开启                     |
| -------- | ------------------------------------------------------------------------------ | -------------------------------- |
| 人物立绘 | hover 姓名显示点击提示；点击姓名后获取、显示并缓存，再次点击或点击其他位置收起 | hover 姓名时获取、显示并缓存     |
| CG       | 对应位置显示“查看 CG”按钮；点击后获取、显示并缓存                              | 阅读到附近位置时获取、显示并缓存 |

“保存”指写入插件的本地内容缓存，不是另存到系统下载目录。已有缓存直接复用，同一资源只缓存一份。

不会因为打开章节就主动下载整章图片；自动显示关闭时，仅 hover 姓名或滚动经过 CG 位置都不应发起图片请求。关闭开关不会删除已有缓存。

## 按需缓存，默认 7 天未使用后清理

- **目录更新（2026-11-04 确认）**：每次重新打开阅读器自动联网检查一次剧情目录与篇目列表；有可用缓存时先显示缓存，再更新目录。页面内部导航不重复触发。总目录顶部提供“刷新目录”，与自动检查使用相同逻辑，显示刷新中、成功和失败，进行中的重复操作合并。
- **刷新边界**：目录检查独立于缓存保留期，不靠清缓存发现新剧情。仅更新目录与篇目列表；正文仍在进入对应剧情后按现有规则准备，已缓存正文的修订仍由“刷新本章”获取。目录刷新不批量重新下载正文、映射或图片，不修改阅读记录、设置或当前阅读位置。新增篇目的未知字数不能计为零。
- **刷新失败**：网络失败、目录空白或结构不兼容时保留原可用目录，显示失败原因并允许手动重试；没有缓存且无法取得目录时保留启动错误与重试入口。新目录通过完整解析后才替换缓存，清理内容后的迟到结果不能回填。打开时检查不增加常驻后台任务。
- **正文**：打开一部剧情后自动加载该部全部篇章正文；重读优先使用缓存。“刷新本章”只重新获取该篇并更新正文与字数，例如源站修订文本时使用，日常阅读无需手动刷新。实现默认最多两篇同时加载，避免集中请求源站。
- **资源映射**：获取后缓存，供多个章节复用，避免重复请求。
- **图片**：仅在上节规定的触发条件满足时获取并缓存，不预下载整库或整章。
- **保留期**：文本、资源映射和图片默认在最后一次使用后保留 7 天，期限可调整；不是下载满 7 天就删除仍在使用的内容。
- **容量**：暂不设置图片缓存容量上限。
- **手动清理**：提供“清理图片缓存”和清理全部正文／资源的独立操作。2026-11-03 后续反馈要求后者名称更明确；实施默认文案为“清理剧情文本和图片缓存”，说明中列出同时清理资源映射、保留阅读记录。实际清理范围仍为文本、资源映射和图片，不与“清除全部阅读记录”混淆。
- **历史独立保存**：缓存清理和到期不删除浏览历史、阅读位置；清除历史是单独操作。
- **阅读记录清除**：支持当前剧情和全部剧情两个范围，均保留设置、内容缓存与公共字数统计。清除后进度归零，最近阅读改指仍保留的最近实际阅读篇目；全局清除后隐藏最近阅读入口并回到总目录。已在途的旧页面保存不能恢复被清除的记录，重新打开正文后才能开始新的阅读记录。
- **不主动补下载**：清理全部内容时停止当前正文预取队列，清理后不立即重新下载；再次打开剧情／篇目或主动重试时才能重新获取正文，图片仍按既有查看条件获取。

实现建议是打开阅读器时检查、清理过期缓存，不额外常驻后台。具体检查时机属于实现默认，尚未单独确认；关闭期间不承诺到第 7 天准时执行清理。

当前不做全量离线包、后台定时同步或跨设备缓存同步。
