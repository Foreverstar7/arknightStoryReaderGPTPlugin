# 0.1.20：阅读记录清除与全库正文检查

验证日期：2026-11-03。基线为 main 的 `fdd970e`／0.1.19；本轮按用户反馈实现和本机验证，未提交、推送或发布，不进入 S5。

## 页面与记录

- 各剧情篇目页新增“清除本剧情阅读记录”，明确剧情名称、确认／取消、进行中与失败重试；清除后留在该部目录，其他剧情的进度和续读位置保留。
- 设置的缓存分类改为“数据管理”，依次放清理图片缓存、清理全部内容缓存、**清除全部阅读记录**；位于“最近阅读”之前。清记录保留内容缓存、设置和公共字数统计。
- 全局清除后回总目录；单部清除后最近阅读指向剩余记录中实际最近的一篇。没有记录时禁用清除按钮。
- 复用既有 `reader_clear_history`，可选 `storyId` 指定当前剧情，空对象保持全局语义；严格拒绝未知参数，防止拼错作用域后误清全部。仍为 10 个 app-only 工具。
- 修复恢复滚动／离开正文时迟到保存的竞态。页面排空保存队列，持久化全局／单剧情清除代次，并将打开正文得到的 token 随位置保存提交；另一新版进程中的旧页面也不能重新写回已清记录。重新打开正文后可开始新的记录。旧客户端不具备此保护，需重启桌面客户端统一使用新版本。
- 正文准备失败详情可直接展开查看篇目和原因，不再只能依赖悬停提示。分母不全时继续显示“—”，不把失败篇目按零字数计算。

公开证据：[G2H/END](https://prts.wiki/w/G2H/END)、[0-4 混战/BEG](https://prts.wiki/w/0-4_混战/BEG)、[7-10 暗淡者之火/END](https://prts.wiki/w/7-10_暗淡者之火/END)。分支语义另核对 PRTS [Widget:ScenarioSimulator](https://prts.wiki/w/Widget:ScenarioSimulator) 的 decision、predicate 与 LOG ALL 处理。

末尾返主页不含正文，只接受已观察到的 `dest=home` 且无后续脚本形式；重复参数只接受值相同的情况，冲突仍显式失败。复杂分支按来源顺序标注到达条件、隔离人物状态，共同内容只输出一次。未修改既有简单分支的结构和修订号；只有原先被拒绝的复杂控制流使用 v2。没有逐剧情 ID 例外或猜测资源地址。

两部 34 篇的正文与选项独立字数统计均与解析结果相符；浏览器准备了全部 34 篇，并实际打开五篇原先失败的正文，验证全剧情分母及进度显示。这个字数复核不等于逐张图片或所有立绘已经验收。

## 可重复命令

```powershell
./scripts/npm.ps1 run audit:chapters
./scripts/npm.ps1 run audit:chapters -- --offline
./scripts/npm.ps1 run audit:chapters -- --refresh
```

默认复用 `.ai/local/prts-chapter-audit/` 的公开文本；`--refresh` 重新取源，`--offline` 只回放本机样本，两者不能同时使用。审计有失败时退出码为 1，同时仍写完整报告。脚本不打开真实运行数据根、不读取或修改用户记录、不获取图片；正常产品仍只准备当前剧情。原始文本不提交也不打包，公开报告只含标识、计数、来源和错误元数据。
