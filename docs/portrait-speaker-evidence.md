# 立绘对应关系与显示方式

匹配规则处理“场景画面沿用，但发言人已经切换”造成的身份假冲突。姓名保持剧情原文，场景资源与发言人分别处理；没有增加逐姓名或逐 NPC 的资源表。

## “妻”的问题来自哪里

核对来源：[PRTS BW-ST2 隔墙有你/NBT](https://prts.wiki/w/BW-ST2_%E9%9A%94%E5%A2%99%E6%9C%89%E4%BD%A0/NBT)。

该篇中夫使用 `avg_npc_140`，妻使用 `avg_npc_141`，两者都存在独立单人展示。妻的部分反应对白沿用了丈夫的单人画面；旧规则把这些画面也当作妻的身份依据，于是认为妻同时对应两个角色，连较早的多人场景也退回中性占位。核对时妻的身体图和表情图均取得 HTTP 200，不能归因为来源没有她的立绘。

修正后，妻在自己出现的场景中保留指定立绘；画面沿用丈夫时，自动显示已由同篇独立展示确认的妻的同造型默认立绘，同时明确提示场景与发言人不一致。用户仍可选择右侧查看原场景中的丈夫立绘。

## 通用匹配规则

1. 继续优先使用来源中的精确资料名、干员 ID，以及同篇同分支容器的一致单资源关联，不使用焦点猜说话者。
2. 资源画面变化后，该画面开始时的具名发言可提供独立展示线索。只有自己的独立线索一致，且其他冲突全部可解释为沿用另一位独立确认角色的画面时，才排除这些假冲突。仅有画面沿用、匿名归属、独立展示本身冲突或不同造型仍不足以确认。
3. 当前画面中能确定发言人的具体表情时优先该表情。同角色同造型有多个表情无法选择，或指定图片确认缺失时，才使用有来源的同造型默认图。
4. 当前只展示其他人或没有角色画面，但发言人已由同篇独立线索确认时，可显示其默认图；元数据保留未展示发言人的原因，正常图片下方不重复说明，没有画面也不标为不一致。跨篇、跨分支和未知造型不外推。
5. 角色、造型、引用、来源缺图与网络／解析错误在结构化结果中分别保留，阅读记录不参与匹配。界面无图时只显示“暂无可显示的立绘”和来源链接，不推断源站不存在图片；不再显示灰色人形与长诊断。立绘仅在网络失败时提供重试按钮。

资源地址和默认图仍由既有 PRTS 映射与图片适配器解析，没有凭名称拼接图片地址。规则证据只在当前篇目与分支容器内有效；源站指令或资源协议改变时，应复核解析、绑定专项与真实篇目，不添加姓名补丁绕过问题。

## 双选控件

有可选图片时，浮层保留方形双段选择：左侧“默认立绘”，右侧“场景立绘”。角色一致时仍保留，默认图与剧情指定表情可能不同。首次打开优先可确认的场景表情；已确认原画面只显示其他人时显示发言人默认图。选择只影响当前浮层，不持久化为偏好，也不改变阅读记录。两种图片都不可用时隐藏控件。

直接悬停选项显示区别，并为单选控件提供相同的无障碍说明，不增加 i 图标：

| 选项     | 说明                                           |
| -------- | ---------------------------------------------- |
| 默认立绘 | 该角色当前造型的基础立绘，不代表本句剧情表情。 |
| 场景立绘 | 剧情当前画面使用的立绘，可能与发言人不一致。   |

已经确认不一致时，图片上方常驻“场景立绘与发言人不一致”。仅无法确认对应关系时，上方写“尚未确认角色与立绘的对应关系”，不当作已证实的不一致。图片下方不重复说明显示模式，也不提供成功状态的刷新按钮。原场景存在多个未确认候选时并列显示，既不任取一人，也不为显示完整场景而确认身份。

可靠默认图未确认时左侧置灰，没有场景资源时右侧置灰。切换与重试继续按需加载；已经确认的默认模式不先读取场景表情。原生单选控件支持方向键；超出已有图片组合上限时明确报错，不删去其中的角色。

“自动显示图片”仍默认关闭：点击姓名打开，再次点击、点击外部或 Esc 关闭。开启后才有悬停预览、离开关闭和点击固定。

## 验证范围

绑定专项覆盖画面沿用造成的假冲突、独立身份／造型真冲突、匿名、分支隔离、无画面、多个场景候选及网络错误；MCP 专项检查 default／scene 选择确实传入图片来源。

公开样本回放曾覆盖 1,756 篇正文，无解析失败。覆盖统计仅说明绑定规则，不等于图片链路净修复数，也不证明全库图片可用。真实 PRTS 浏览器专项检查了妻的反应对白，默认图与原场景均可切换，并保留不一致提示。

页面检查覆盖四种窗口、双主题、方向键、焦点返回、无资源禁用和浮层边界。网站使用原创兔子替身，其截图不能作为真实人物对应证据。命令与当前验收边界见 [验证指南](testing.md)和 [STATUS](../.ai/STATUS.md)。
