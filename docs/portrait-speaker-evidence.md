# 立绘对应关系与显示方式

本次修正针对“场景画面沿用，但发言人已经切换”造成的身份假冲突。姓名保持剧情原文，场景资源与发言人分别处理；没有增加逐姓名或逐 NPC 的资源表。

## “妻”的问题来自哪里

核对来源：[PRTS BW-ST2 隔墙有你/NBT](https://prts.wiki/w/BW-ST2_%E9%9A%94%E5%A2%99%E6%9C%89%E4%BD%A0/NBT)。

该篇中夫使用 `avg_npc_140`，妻使用 `avg_npc_141`，两者都存在独立单人展示。妻的部分反应对白沿用了丈夫的单人画面；旧规则把这些画面也当作妻的身份依据，于是认为妻同时对应两个角色，连较早的多人场景也退回中性占位。核对时妻的身体图和表情图均取得 HTTP 200，不能归因为来源没有她的立绘。

修正后，妻在自己出现的场景中保留指定立绘；画面沿用丈夫时，自动显示已由同篇独立展示确认的妻的同造型默认立绘，同时明确提示场景与发言人不一致。用户仍可选择右侧查看原场景中的丈夫立绘。

## 通用匹配规则

1. 继续优先使用来源中的精确资料名、干员 ID，以及同篇同分支容器的一致单资源关联，不使用焦点猜说话者。
2. 资源画面变化后，该画面开始时的具名发言可提供独立展示线索。只有自己的独立线索一致，且其他冲突全部可解释为沿用另一位独立确认角色的画面时，才排除这些假冲突。仅有画面沿用、匿名归属、独立展示本身冲突或不同造型仍不足以确认。
3. 当前画面中能确定发言人的具体表情时优先该表情。同角色同造型有多个表情无法选择，或指定图片确认缺失时，才使用有来源的同造型默认图。
4. 当前只展示其他人或没有角色画面，但发言人已由同篇独立线索确认时，可显示其默认图；没有画面说明“当前未展示发言人”，不标为不一致。跨篇、跨分支和未知造型不外推。
5. 角色、造型、引用、来源缺图与网络／解析错误分别说明。中性占位不表示源站没有图；错误保留重试，阅读记录不参与匹配。

资源地址和默认图仍由既有 PRTS 映射与图片适配器解析，没有凭名称拼接图片地址。规则证据只在当前篇目与分支容器内有效；源站指令或资源协议改变时，应复核解析、绑定专项与真实篇目，不添加姓名补丁绕过问题。

## 双选控件

浮层统一保留方形双段选择：左侧“默认立绘”，右侧“场景立绘”。角色一致时仍保留，默认图与剧情指定表情可能不同。首次打开优先可确认的场景表情；已确认原画面只显示其他人时显示发言人默认图。选择只影响当前浮层，不持久化为偏好，也不改变阅读记录。

直接悬停选项显示区别，并为单选控件提供相同的无障碍说明，不增加 i 图标：

| 选项     | 说明                                           |
| -------- | ---------------------------------------------- |
| 默认立绘 | 该角色当前造型的基础立绘，不代表本句剧情表情。 |
| 场景立绘 | 剧情当前画面使用的立绘，可能与发言人不一致。   |

已经确认不一致时，图片上方常驻“场景立绘与发言人不一致”，下方说明当前显示哪一种图片。仅无法确认对应关系时，写“尚未确认角色与立绘的对应关系”，不当作已证实的不一致。原场景存在多个未确认候选时并列显示，既不任取一人，也不为显示完整场景而确认身份。

可靠默认图未确认时左侧置灰，没有场景资源时右侧置灰。切换与重试继续按需加载；已经确认的默认模式不先读取场景表情。原生单选控件支持方向键；超出已有图片组合上限时明确报错，不删去其中的角色。

“自动显示图片”仍默认关闭：点击姓名打开，再次点击、点击外部或 Esc 关闭。开启后才有悬停预览、离开关闭和点击固定；本次没有更改这一交互。

## 对比用户提供的网站

核对页面：[ASS 对应篇目](https://ass.m-j.bond/story/activities/act13mini/level_act13mini_st02/)。核对了该站部署的[篇目数据](https://image-1258734717.cos.ap-beijing.myqcloud.com/ASSD/zh_CN/activities/act13mini/level_act13mini_st02.json)和[页面组件](https://ass.m-j.bond/_app/immutable/nodes/6.a92a22ea.js)，没有取得其后端数据生成源码，也没有完成该站实际 UI 验收。

- 该页面按行直接使用 `figure`，点击打开图片；没有 `figure` 时不显示图片，仍提供 PRTS 搜索入口。
- 多数妻的行使用 `Avg_avg_npc_141-1.png`，夫使用 `Avg_avg_npc_140-1.png`。
- 妻的反应行 `id=92` 使用的仍是丈夫的 `Avg_avg_npc_140-1.png`，部分夫／妻对白没有 `figure`。因此该站能够展示图片，并不能证明每张图都与发言人一致。

以上只说明核对时公开部署代码与数据的行为，不能据此推断它如何生成角色映射。其数据和代码未复制到产品中。

## 核对范围与结果

- 对已有 1,756 篇公开正文样本重算同篇绑定：解析失败 0；107 篇新增 1,358 处可确认的多人场景绑定；旧绑定丢失 0、变化 0。这是绑定规则覆盖统计，不是完整图片链路的净修复数量，也没有全库下载图片。
- 实际读取妻／夫的 17 个绑定样例：妻在多人场景中使用自己的指定图，沿用丈夫画面时使用自己的默认图；丈夫保持自己的图。另核对《孤星》CW-6 塞雷娅与《尘影余音》LE-6 别格勒的原始资源，指定表情可加载。
- 专项覆盖假冲突、独立身份／造型真冲突、匿名归属、分支隔离、无画面、默认与原场景切换、多个原场景候选、默认图加载不依赖失败的场景表情，以及网络错误保留。
- 网站示例控件检查四种窗口与双主题：320×760、768×900、1440×960、1024×400；覆盖方向键、焦点返回、无资源禁用及浮层边界。网站继续用原创兔子替身，不把示意图当作真实人物对应证据。
- 真实 PRTS 浏览器专项验证妻的反应对白：默认与原场景可分别查看，图片内容不同，两边均保留不一致提示，方向键可切回。

最终立绘相关的 22 项检查、插件类型与构建、网站类型与构建均通过。实际执行的命令、浏览器专项结果和未覆盖项见 [.ai/STATUS.md](../.ai/STATUS.md)。本轮使用隔离缓存与测试数据；没有清理或修改私人阅读记录。尚未对新实现进行真实桌面已安装插件验收，既有已冻结的 1.0.1 归档不会自动包含这些本地修改。
