# 0.1.23：打开时自动检查目录与手动刷新

日期：2026-11-04。基线：`5d74ea1`／0.1.22，开始时工作区干净。

## 用户可见行为

每次重新打开阅读器，先显示可用的本地目录，同时联网检查 PRTS 最新目录。总目录标题右侧增加“刷新目录”，显示刷新中、成功或失败。请求中重复点击合并；键盘焦点保留，按钮可触摸操作。首页、篇目列表和正文之间切换不会额外触发自动检查。

刷新只更新剧情目录和篇目列表，方便发现新增剧情和新增篇目。正文仍按进入当前剧情后的既有准备规则加载；已缓存正文的修订仍使用“刷新本章”。7 天未使用后的缓存清理与目录更新分开，不需要清空正文和图片来发现新剧情。

网络失败、空目录和源结构不兼容保留原可用目录，并显示原因与重试入口。无缓存且两个启动请求都失败时，显示原启动错误。当前阅读位置、最近阅读、最远已读、设置和清除记录的结果不会被迟到的目录响应覆盖。

## 实现边界

- `reader_snapshot({ refreshCatalog?: boolean })` 兼容原空对象，MCP 工具仍为 10 个且全部 app-only；复用当前 SDK、Zod、SQLite、React，无新增依赖或宿主 API。
- 启动读取缓存与主动检查并行；同一服务／同一缓存代次的冷启动请求共用一个网络 Promise。暖缓存可立即返回，不等待主动检查。
- 仅重新获取“剧情一览”与“模板:剧情导航”，两页完整解析通过后再替换目录缓存。没有先删缓存；原有缓存代次阻止清内容前的迟到结果回填。
- 刷新响应只替换公共目录并合并较新字数；常规导航快照只更新记录与字数，不能使目录退回旧版。当前阅读组件不重新挂载，总目录通过既有卡片锚点保留可见位置。新篇目的字数未知时仍保持未知。
- 自动检查以 UI 实例初始化为一次打开，不在窗口重新获焦、内部导航或设置保存时反复检查，也不创建常驻同步任务。宿主复用隐藏 UI 而不重新创建实例的行为，本轮没有实际宿主证据。

实测修复了一处产品问题：原生 disabled 会让正在操作的刷新按钮丢失焦点，改用 `aria-disabled` 与事件守卫后保留可见焦点。相对于交互稿，本轮增加标题右侧刷新按钮和一行目录状态；保留原色彩、分类导航、卡片与篇目轴。失败长提示在 320px 换行，低高度内容可滚动。

首次浏览器启动被沙箱回环端口权限阻止，改用允许本机 HTTP 的隔离测试运行后正常执行；不是产品连接失败。所有写入测试与探针使用 `.ai/local/`，未使用真实阅读记录目录。
