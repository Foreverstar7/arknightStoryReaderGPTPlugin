# 全篇 CG 与角色立绘审计（2026-11-04）

结论：**当前版本不能保证全部角色头像和所有 CG 入口可用**。源脚本中的普通 CG 地址均存在；主要缺口是人物映射适配、特殊 CG 指令未进入阅读器，以及场景无法确定说话者。

本次以 main 的 `f5df065`、阅读器 0.1.21 为基线，核验 117 部／1,756 篇。1,756 篇在北京时间 2026-11-04 19:42 的源站修订 SHA-1 与本地公开样本全部一致，正式解析及独立引用扫描均无失败。没有修改产品解析、安装包或阅读记录。

## 统计口径

- “资源引用种类”按资源引用（含表情／分组／空白差异）去重，**不是角色人数，也不是 PNG 文件数**；一个立绘可能需要底图与表情两张文件。
- “脚本出现次数”统计原始指令加载引用的次数；同一张图重复出现分别计数。
- “点击失败发言块”按当前正式解析及服务端人物选择规则统计；连续同名、同场景的多段发言合并为一个块。分支全部纳入，共同后续只计一次。只在场景恰有一个不同资源时才进入映射解析。
- “影响篇目”对该行去重，不同原因可以落在同一篇，不能简单相加。

### 1. 映射键大小写不一致：程序适配问题

`resolvePortrait` 把请求引用转为小写，但直接拿它查原始 `character.json` 的键；该 JSON 保留了 `char_1508_Faust_1`、`char_1507_Mephisto_1`、`char_259_Jessica_1` 等含大写字母的键。源站当前 context 模块会先把映射键也统一为小写。

本次只在审计中构造同样的小写键视图，102 种失败引用均能准确解析并取得有效图片头；没有修改正式解析器或改变任何人物姓名。

### 2. 引用含空白：源文瑕疵与解析容错缺口

49 种原始引用含多余空白，例如 `char_002_amiya_1#7␠`、`avg_4179_monstr_1#4$1␠`，以及 `avg_4236_tmslot_1#3␠$1`（这里用 ␠ 展示空格）。生产引用正则不接受这些形式。

审计删除空白后，49 种都能按明确的 body/index 找到有效图层，证明存在可核对的候选；这仍是诊断证据，尚未决定或实施生产容错规则。点击受影响的 7 篇：[0-10 困境/BEG](https://prts.wiki/w/0-10%20%E5%9B%B0%E5%A2%83/BEG)、[1-1 孤岛/BEG](https://prts.wiki/w/1-1%20%E5%AD%A4%E5%B2%9B/BEG)、[17-17 不曾怀疑/END](https://prts.wiki/w/17-17%20%E4%B8%8D%E6%9B%BE%E6%80%80%E7%96%91/END)、[MT-6 告解/BEG](https://prts.wiki/w/MT-6%20%E5%91%8A%E8%A7%A3/BEG)、[MT-8 朝圣/END](https://prts.wiki/w/MT-8%20%E6%9C%9D%E5%9C%A3/END)、[TO-3 露营奇“叽”/END](https://prts.wiki/w/TO-3%20%E9%9C%B2%E8%90%A5%E5%A5%87%E2%80%9C%E5%8F%BD%E2%80%9D/END)、[TO-9 绘我们的黎明/END](https://prts.wiki/w/TO-9%20%E7%BB%98%E6%88%91%E4%BB%AC%E7%9A%84%E9%BB%8E%E6%98%8E/END)。

### 3. 新版映射遗漏：旧版资源仍存在

涉及 `avg_npc_598_1` 与 `avg_npc_604_1` 两个基础编号、17 种表情引用。当前 `character.json` 没有这两个键；旧版 `Widget:Data_Link` 与 `Widget:Data_Char` 仍有按相同表情／分组匹配的明确条目。17 种旧地址都通过在线检查。

因此不能说源站没有图片；准确原因是当前数据入口未覆盖这些仍在旧索引中的资源。点击受影响的 5 篇：[BW-ST1 向左向右/NBT](https://prts.wiki/w/BW-ST1%20%E5%90%91%E5%B7%A6%E5%90%91%E5%8F%B3/NBT)、[BW-ST3 扬尼与我/NBT](https://prts.wiki/w/BW-ST3%20%E6%89%AC%E5%B0%BC%E4%B8%8E%E6%88%91/NBT)、[BW-ST5 一次重逢/NBT](https://prts.wiki/w/BW-ST5%20%E4%B8%80%E6%AC%A1%E9%87%8D%E9%80%A2/NBT)、[BW-ST6 别太紧张/NBT](https://prts.wiki/w/BW-ST6%20%E5%88%AB%E5%A4%AA%E7%B4%A7%E5%BC%A0/NBT)、[BW-ST4 告别时刻/NBT](https://prts.wiki/w/BW-ST4%20%E5%91%8A%E5%88%AB%E6%97%B6%E5%88%BB/NBT)。

### 4. 特殊引用未支持

`$ill_amiya_normal` 位于 [隐藏剧情/剧情](https://prts.wiki/w/%E9%9A%90%E8%97%8F%E5%89%A7%E6%83%85/%E5%89%A7%E6%83%85)，出现 3 次、对应 3 个发言块。它不符合目前的人物引用语法，所核对的新旧人物映射也没有可直接确认的对应资源。本次没有猜测阿米娅的替代图片；不能将其宣称为已确认的服务器 404。

## 验证与边界

- 对当前清单及诊断候选合计 **13,390 个不同图片 URL** 逐一请求 `Range: bytes=0-65535`，全部 HTTP 206、PNG MIME 与真实图片头一致、宽高有效、文件大小在现行预算内；没有未核验地址、404、网络失败或格式失败。
- 失败引用中，除特殊 `$ill_amiya_normal` 外，168 种通过明确的大小写／空白诊断或旧版显式索引找到了可访问候选。它们仍计为**当前产品失败**，没有以诊断成功冒充已修复。
- 检查的是定位、在线可访问性、MIME、尺寸及大小上限；**未下载全部原图，未对每张图做完整解码，也未逐篇验证桌面宿主显示与说话者身份**。不把此结果扩写为全库图片 UI 验收。
- 未核验视频画面、动态特效、道具 ShowItem 及纯变换／隐藏指令；本报告的 CG 全量指静态 CG 加载指令，角色全量指 Character／CharSlot／CharacterCutin 加载引用。常规背景另外列出。
- 首次完整地址扫描、补充诊断扫描均无最终失败；最后离线复跑 0 网络请求。正式 CG 独立源指令计数与解析产物同为 2,365，所有场景人物引用都能追溯到原始加载指令。
- `./scripts/npm.ps1 run check` 通过：类型、65/65 测试及格式；最终报告脚本离线复跑及统计自检通过。本轮没有改 UI／正式运行逻辑，因此未重跑 UI 截图验收或安装插件。
