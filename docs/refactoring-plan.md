# 保持功能的重构计划

日期：2026-11-03。功能基线：**`e3d34cb`／0.1.21**。状态：已规划，尚未实施。用户允许大幅重做内部结构，要求现有功能保持、减少不必要的防御性编程，并参考高质量规范与仓库。

建议先收紧数据与状态模型，再统一职责，最后删除被这些约束替代的重复判断。验收看错误是否更容易定位、状态是否更少歧义、行为是否保持，不用删掉多少 `if` 或缩短多少行作为目标。外部源数据、磁盘数据和异步竞争仍有真实不确定性，这些检查必须有明确归属。

TanStack Query 的采用门槛：禁用与当前产品不符的自动重试、聚焦／重连刷新和轮询；明确 staleTime／gcTime 与显式失效，不能在组件重挂载时偷偷回源。官方默认行为包含后台刷新与失败重试，必须逐项配置并用源调用计数验证。[默认行为](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults)

资料、封面等读取可以进入 query；**实际打开正文会生成 historyToken 并迁移记录，不能直接缓存 `reader_chapter` 的返回值来跳过打开动作**。保存、清历史、清缓存是显式命令，确认服务成功后更新权威状态；失败回滚、清理后不复活、旧版本统计不覆盖新版本仍由领域和持久层保证。Query 的 AbortSignal 只有消费并传入下游才会取消对应工作，且不是数据库回滚机制。[取消语义](https://tanstack.com/query/latest/docs/framework/react/guides/query-cancellation)

每个新候选的试验均需交付：能删除的现有通用实现、锁定的稳定版本与 Node／React／TypeScript 兼容证据、包体／启动影响、原行为回归结果，以及采用或放弃的具体理由。正文两并发调度可以只用 p-limit；没有复杂优先级／暂停需求时不同时引入更大的队列库。若 TanStack Query 不适合某个有副作用的调用，保留窄的命令函数，不能因此再造一整套查询框架。PRTS 自定义语义没有现成播放器阅读模型可直接替换，复用 parser 工具也不能省去语义验证。

## 减少防御代码的具体准则

1. **入口检查完整，内部模型可信。** PRTS、HTTP、MCP、数据库行和旧 JSON 分别在进入系统时解码；语法合法还需检查返回 ID／请求 ID 等业务对应关系。已经解码的同一进程内对象不在每层反复 parse；重新穿过磁盘或网络仍是新边界。
2. **缺失是业务状态时显式表示。** 字数未知、视频无文字、来源缺失、修订待核对各有类型；不能用 `0`、空字符串或空数组替代。旧数据允许缺少代次等字段，但读取后的内部模型应有确定默认值，业务代码不再到处 `?? 0`。
3. **先建立不变量，再删判断。** 例如内部 `DecisionCommand` 使用配对后的选项对象，而非两份可长短不一的数组；仍保留多余源 values 的诊断语义。直接删除 `values[index]` 检查并加 `!` 不算改进。
4. **错误只在能处理或需要转换的地方捕获。** 恢复缓存、向用户报告、补充存储上下文是明确职责。已经展示失败后丢弃事件 Promise、预期动画取消须写清所有者与原因；不能用空 catch 把未知编程错误一并消失。
5. **异步保护依据并发模型保留。** 导航请求序号保护画面，historyToken 保护跨进程迟到保存，cache epoch 保护清理后回填，修订 CAS 保护新版统计。它们保护的对象不同，不能简单合并成一个布尔值或一个“通用版本号”。
6. **不为假想扩展建立框架。** 使用普通函数、有限联合与小模块；不自建插件注册平台、通用工作流、ORM 或状态框架。需要通用调度／查询能力时先按上表验证成熟依赖，满足要求就复用，不把“不加依赖”本身当质量指标。

建议 API 形状是 `call<K extends ToolName>(name: K, input: ToolInput<K>): Promise<ToolOutput<K>>`。实现必须由真实 schema／分支证明类型关联，不能最终用 `as ToolOutput<K>` 绕过检查。固定十个工具时，清楚的穷尽 switch 也可优于难以理解的泛型注册框架。

## 分步实施

推荐顺序 **R0 → R1 → R2 → R3 → R4 → R5**。每片都集成到可运行阅读器并形成独立本地提交；不是先拆完整个后端再补前端。现阶段可直接开始的是 R0；本文件不表示 R0 已实施。

### R0：建立可以证明功能不变的基线

- 产物：在现有审计工具增加可比较的语义指纹模式，包含正文与选项顺序、block ID、分支归属、人物 scene、视频链接、诊断、总字数。引用 0.1.21 的源 SHA256；本机已有 1,756 篇 raw 只读回放，不向 Git 加入整库正文。
- 把必要的独立源行计数方法整理成可重复维护脚本；测试保留原创小样例，特别覆盖嵌套 Decision、共用值、未知条件、multiline 跨演出、动画文字和视频。总字数一致不足以证明人物／分支正确，必须同时比较结构与 ID。
- 将真实记录复制品的迁移测试与真实原文件哈希核对流程写入维护说明；禁止测试指向用户运行目录。冻结已有浏览器关键行为，不新增逐行复刻实现的测试。
- 验收：当前基线自比无差异；故意改变原创例子的正文、分支、scene 或 ID 能被比较器检出；没有额外产品下载。缺 raw 时明确缺样本，不能把缺样本当通过。
- 回退：此片只有测试／维护能力，可独立撤回，不改数据格式。以后任何“等价”主张必须说明使用的基线和覆盖范围。

### R1：让“取一篇正文并显示错误”在两种传输中有同一契约

- 依赖 R0。先贯通 snapshot／chapter／prepare，再按原样迁入其余工具；同一提交中的 HTTP 和 MCP 均可运行。
- 同步建立依赖选择记录，验证 TanStack Query 的小路径和 SDK 取消参数；新依赖可用则复用，不先实现通用请求管理器。实际打开／写入命令不变成可跳过的缓存读取。
- 在 shared 定义输入／结果类型的权威关系。transport 解码成功结果和安全错误，service 接收已验证入参；明确哪些 SDK 入口已验证、哪些 HTTP 入口必须验证，避免叠加无意义的重复 parse。
- 保持 `ReaderError`，外部未知异常在适配处转换并保留 cause；页面共用错误呈现函数。未知 host 拒绝仍为 unknown，不能归成 PRTS 网络失败。无结果／资源缺失／parse／storage／conflict 继续区分。
- 验收：错误参数、错篇目返回、无效结果、服务错误、宿主拒绝及图片分段错误保持原安全行为；现有 MCP 和真实正文路径通过；工具名、URI、可见性无变化。
- 回退：只改内部调用类型和解码归属，不改 wire 字段或数据库；可回退这一提交。暂不改变旧 UI／服务成套更新要求。

### R2：统一正文获取，保持“准备”和“阅读”的副作用区别

- 依赖 R1。抽出一个正文仓储／加载模块处理缓存命中、v3 本地重解析、主动刷新和公共字数验证；保留源读取与持久事务的明确分界。
- 准备路径只取得内容并更新公共统计；打开路径在其上执行修订迁移、生成 historyToken 和定位／图片索引。不要设计 `load({saveHistory, migrate, refresh, ...})` 让任意布尔组合进入内部。
- 旧记录／索引在读取边界规范化；未知进度用领域状态表示，暂保留旧 wire 表示的兼容编解码。字数、内容类型和有效修订关系只在领域模块判定。
- 验收：离线旧 raw 升级不回源；预取前后记录完全相同；打开才迁移；清缓存后滚动不补正文；刷新冲突不覆盖新记录；两进程迟到统计仍被 CAS 拒绝。R0 指纹无变化。
- 回退：优先不改持久格式。若证明必须改变格式，先交付备份／读取旧版／失败保留方案及迁移回归，之后再变更；不得用删除缓存或清用户记录解决升级。

### R3：集中导航与保存生命周期，保持原来的阅读过渡

- 依赖 R2。用 reducer／普通状态转换函数表达当前画面、正在打开的目标、错误及重试意图；目录以 ID 引用权威 snapshot，旧画面在转场期间显式持有，不因去重而提前卸载。
- 采用已通过小路径验证的请求管理候选；p-limit 的两并发、clearQueue 和等待 Promise 收敛验证与本片一起完成。若不采用，记录实际不匹配点；不扩写自己的通用查询／队列系统。
- 将 DOM View Transition／Web Animations 适配与数据请求分开；请求任务只有当前拥有者能提交结果。保留关闭／切页前 flush 和保存队列去重，不能为了减少 refs 丢掉跨操作时序。
- 从 Reader 提取位置观察、恢复和排队保存的内聚模块；事件触发读写，效果用于 DOM／宿主生命周期。保留实际滚动锚点、最后／最远分离和纯视频不保存规则。
- 验收：初始续读与点主页交错、慢打开后快速切换、同篇最近入口、前后篇、清历史与迟到保存、保存失败重试、 resize／减少动态效果终态一致；固定来源条不参与快照、首张封面不闪空。
- 四窗口及浅深主题实际操作并对照设计。回退以页面内部状态提交为单位，无持久数据迁移，不用新增永久功能开关留双套状态机。

### R4：一次解析源脚本，减少语法与控制流的互相防御

- 依赖 R0、R2；安排在 R3 后便于定位回归。先仅抽出字段边界与 tokenizer，输出带位置的命令；保持现有输出投影。随后将参数规范成 `Speech`、`Decision`、`Predicate`、`Video`、`StageOnly` 等有限指令类型。
- 在继续扩写 tokenizer 前对 Chevrotain 做有界试验；若成熟工具更好地满足转义、来源位置、严格失败和全库等价要求，就直接采用。若已有窄 scanner 更清楚且迁移无收益，给出比较证据，不以个人偏好决定自研。
- 兼容拼写在源适配处处理并附证据编号／来源诊断。领域阶段不再处理任意 `Record<string,string>`；仍区分未支持语法与可说明的源异常，不全局忽略未知命令。
- 用一次控制流分析选择明确的简单／复杂投影，替代抛 ComplexFlow 后重跑。最终可以统一中间表示，但**不要求把两种输出强行变成同一种形状**：稳定 block ID、段落分组和旧锚点本身是兼容契约。
- 最大不确定性：统一控制流能否同时保留所有既有分组和人物状态。先以原创复杂拓扑与全部 1,756 篇快照做有退出条件的试验；只有结构、ID、字数、scene、诊断全部等价才切换。若不能等价，保留明确的双投影，先交付一次扫描与无异常分流，不借“重构”偷偷改变阅读结果。
- 验收：R0 全库指纹零差异、未知指令继续失败、全部来源兼容回归通过，六类真实浏览器样本仍可读。性能比较同一批离线输入，记录耗时与内存，无硬性假定提速比例。
- 回退：不在同一片更改 block ID／revision 算法；新旧解析器只在本机比较工具中并行，不在生产双跑或永久保留两套入口。若确有修正语义需求，应另列功能修复及迁移，不混入等价重构。

### R5：收敛存储边界，审计并删除已经冗余的保护

- 依赖 R1–R4。逐个检查剩余的 schema parse、可选字段默认值、catch、冲突检查和旧格式路径；每次删除说明“不变量由哪一层保证、对应哪项回归”。不按正则批量删除 `?.`、`??` 或 catch。
- 统一数据库行解码和错误上下文的写法；只在真正相同的场景复用事务辅助函数，避免为 reading／index／cache 建通用仓储框架。网络仍在事务外，阅读记录耐久性不随可再取缓存降低。
- 保留 SQLite 跨进程事务、historyToken、cache epoch、统计 CAS、旧 JSON 的防复活标记及文件损坏反馈。旧格式支持只有在用户迁移路径、持久版本和回滚测试齐全后才能单独退役；内部破坏性重构不授权破坏用户数据。
- 验收：所有存储／清理竞态及双进程探针通过；已知取消可安静结束，写入失败必有反馈且保留 cause；真实记录文件校验不变。只有文档／格式变更不重复跑无关整套测试。
- 回退：优先沿用磁盘结构；必须迁移时在操作前建立一致备份，确认没有活动写入，保持旧文件，失败可恢复副本。不能用降低同步级别、增加无限重试或吞异常来消除测试失败。

## 完成标准与执行边界

每片提交前执行相关类型、领域、契约或浏览器检查；全流程稳定后再运行一次 build／check、完整 fixture 与真实 PRTS 回归、1,756 篇离线对比及实际安装包 stdio／双进程／官方加载器检查。需要重新发布本机包时使用新版本目录，保留旧包和真实记录。真实桌面 UI 仍须单独取得体验证据，不能从协议检查推断。

复核时应能回答：一个外部值在哪验证？一个阅读状态由谁更新？一次请求取消后谁还能写？每个必要兼容分支依据是什么？如果只能靠调用者处处补空值才能正确运行，说明结构尚未收敛。

本计划不扩大产品范围：S5 搜索、RAG、整库后台预取、内嵌视频、跨设备同步和发布仍不在本轮。本轮没有实际升级或新增依赖；实施时按上述清单优先复用、核对当时稳定版兼容并实跑，将采用的依赖和锁文件提交。下一轮从 **R0 的比较基线** 开始，随后优先做 R1 和 R2，先减少真实重复检查，再处理最复杂的 UI 与解析器。
