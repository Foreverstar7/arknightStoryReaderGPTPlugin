## 硬编码、冗余防御与过度设计的处理口径

### 硬编码：优先消除来源，必要常量有明确归属

先检查能否从已经取得的源数据、现有配置或明确公式得出。能推导就推导，能删除就删除；把字面量搬进一个巨大 constants.ts 或外部 JSON 并不算去掉硬编码。测试样例可以有明确的固定数据，但不由生产模块导出测试专用剧情。

以下是本次代码抽查发现的候选，**不是已经完成的全量审计或全部可直接删除的清单**：

| 位置／值                                                                                       | 判断与处置                                                                                                         | 验收／归属                                                                            |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| src/data/prts-catalog.ts 的 PRTS_STORY_ID、PRTS_STORY_TITLE                                    | 当前前者只被 tests/prts.test.ts 引用，后者无引用；生产目录无需固化“骑兵与猎人”样例                                 | H1 移到测试样例或删除，目录 ID／顺序完全不变                                          |
| prts-client.ts、prts-portrait.ts、prts-resources.ts 中来源根地址与路径                         | PRTS 的入口和资源路径有来源依据；复用已有 PRTS_ORIGIN，将同一来源配置归到其适配层，保留允许域名与格式检查          | H1 去重复；不增加任意 URL 配置入口，不猜资源名，不额外抓取整站以消除几个常量          |
| prts-cg.ts 的 1280×720 与 640／360                                                             | 原播放器坐标系是必要来源协议；中心点可由画布宽高推导，避免多处独立数字                                             | H1 推导重复值；完整图层位置、顺序、透明度与截图不变                                   |

每个保留的必要固定值都应能回答：为什么通用来源不足、值从哪里来、适用范围、何时检查失效。新增或改变此类选择时同步代码注释、.ai/DECISIONS.md 和交付说明。既有说明可引用，不复制成多套互相冲突的表。

### 防御：入口保证成立后，内部不反复猜测

- 对每个拟删除的判断，记录调用路径、输入类型、保证该条件的不变量及其建立位置。确实不可达的内部状态用明确类型、穷尽分支或更小的函数输入消除，随后删除判断；不添加一个同样多余的异常分支来替换原兜底。
- 已解析的同一进程内对象不在每一层重复 schema.parse；PRTS／HTTP／MCP／数据库及旧文件重新进入系统仍是新的验证边界。ID 对应、分支关系等语义校验与字段类型校验分工明确，不能因为 schema 通过就忽略错误篇目。
- 例：prts-cg.ts 的 pair 已验证长度为 2 且都是有限数字，后面仍以缺项补 0；可在入口得到确定的坐标对。tiledCg 已验证尺寸数量后，再让内部尺寸可能为 undefined 并补 0，也应改成已配对的图片与尺寸。不能以非空断言或强制转换掩盖外部解析失败。
- ReadingState 的旧可选代次可在存储入口规范化一次，内部无需处处 ?? 0；但是“新剧情尚无代次”“人物无资源”“分母未知”是合法业务状态，须明确建模，不能删除后伪造确定值。
- catch 只留在能恢复、补充必要上下文或反馈的位置。检查 ReaderApp／Reader 的每个空 catch：预期动画取消和已由上层展示的失败可有明确所有者；未知程序错误不能被当作成功吞掉。
- 不能用“概率小”代替“不可达”。目录乱序响应、关闭／切页、跨进程清缓存、迟到保存、源文修订都有已有用例；navigation 序号、historyToken、cache epoch 和统计 CAS 保护不同对象，保留相应职责。
- 不为一个已由类型排除的内部不可能状态制造测试数据。验证入口拒绝真实坏数据、正常路径及实际竞态；需要证明新类型约束时用类型检查即可。

### 结构：减少概念和责任混合，不堆层级

已有 ui／domain／data／storage／server／shared 分层继续使用；仅在同一文件存在明显不同变化原因时拆出内聚模块。不按行数拆文件，不建立只有一次转发的 service／manager／repository 链。

| 现有位置         | 应拥有的职责                                     | 不应承担的职责                            |
| ---------------- | ------------------------------------------------ | ----------------------------------------- |
| ui 与组件／hooks | 展示、交互、导航意图、DOM 生命周期与当前页面状态 | 直接解析 PRTS、猜资源地址、决定数据库迁移 |
| domain           | 字数、进度、位置与修订规则等可独立验证的计算     | 网络、DOM、宿主桥接                       |
| data             | PRTS 请求、源结构解析、资源身份与选取规则        | 私人阅读记录更新、组件状态                |
| storage          | reading／index／cache 的边界解码、持久化及事务   | UI 导航、网络请求中的长事务               |
| server           | 打开／准备／保存等用例编排，薄的 HTTP／MCP 适配  | 复制领域规则、承载无关 UI 逻辑            |
| shared           | 真实跨边界契约、错误与跨端策略                   | 无归属工具函数或全局状态的杂物集合        |
| scripts          | 工具链、打包、探针及显式审计                     | 正常阅读时依赖的本机临时路径或全局包      |

每片说明删除了什么重复知识或不必要层次；仅搬动代码且调用路径更绕不算完成。不为未来搜索、官网或更多平台预建插件注册器、通用工作流、查询／队列框架、ORM 或全能资源管理器。已存在的抽象也按真实调用与复用审查，无收益的合并或内联。

## 建议顺序与依赖

2026-11-05 用户授权连续执行整个重构计划；会话过长时，在一个部分完成验证并本地保存后，新开同项目会话接续剩余部分，无需逐片再次确认。候选依赖／解析器整体替换仍按收益条件决定，不把“全部做完”理解为必须采用所有候选。安装、推送、发布和 S5／官网范围不变。

第一批建议为 **R0 → H1 → R1 → R2a → R3a**：先取得当前行为与问题清单，再清理明确冗余、收紧类型与取得正文、目录状态的权威来源。每片都保持阅读器可运行，完成后可停下来体验；这不是发布必须等待全部重构的要求。

### R0：当前行为基线与问题清单

- 从 7724df1 构建基线，记录源码、构建与样本哈希。报告中的 1,756 篇是历史已验证语料；实施时先核对本机 raw 是否齐全，缺失必须单列，不能标作通过。使用 .ai/local/ 中现有公开样本离线回放，不在产品中预取整库。
- 文本指纹包含正文／选项顺序、block ID、分支／共同后续、scene、CG composition、视频、诊断、字数与 revision。以当前 v4 为比较对象；保留独立字数复核，不拿“都能解析”或“总字数相同”替代结构等价。
- 图片基线记录固定来源样本下的原引用、选中资源、original／default／placeholder、原因／证据、图层顺序与几何／透明度。重用已有映射／图片缓存；身份匹配专项独立于旧全库统计，现有审计未覆盖全库身份，不能宣称所有多人物场景都已验证。字节对比用已有文件哈希，不重复下载全部图片。
- 冻结目录初始化与手动刷新、迟到快照、保存／清历史／清缓存、v3→v4 锚点迁移、图片按需及转场的既有用例。保留目标平台与验证方式的区分。
- 在本文件补全待处理清单，每项包含位置、归属、可到达路径或来源、拟删除／推导／保留的理由、对应切片和验证。清单不变成第二套运行配置。
- 验收：基线自比无差异；故意修改原创例子的正文、ID、scene、CG 层能被比较器检出；离线检查记录零网络请求。测试使用隔离记录或一致复制品，不写真实记录。回退只撤回维护能力，无产品／磁盘格式变化。

### H1：先清理可以证明无行为变化的硬编码与结构负担

- 先移走／删除生产模块中的样例剧情常量，再按各自职责收敛重复的来源根地址、画布推导和预算值；版本派生采用最小可行方式。不建一个承载所有模块的配置中心，也不把原来的常量包装为可插拔策略。
- 对没有实际用途、只有转发的层与仅为假想扩展保留的参数，按清单删除或内联；没有具体证据的项目不先贴“过度设计”标签。
- 封面特例及源兼容只做分类；有通用来源替代证据后在 R2b／R4 处理，避免顺便修改已确认显示规则。
- 验收：类型／相关领域与资源测试通过，目录、图片布局、错误预算及版本一致性不变。改到版本或打包时增加实际包重定位探针；改到呈现时按 UI 验收。每次清理独立可回退，不通过删缓存解决兼容。
